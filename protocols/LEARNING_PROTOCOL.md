# Learning protocol

## Purpose

AIDOS becomes more effective by generalizing proven lessons across development goals without importing project-specific truth into the global system.

## Classification

After an execution/review, classify notable knowledge:

1. **Project fact** — remains only in project repo.
2. **Learning candidate** — plausibly reusable but not yet proven/generalized.
3. **Proven AIDOS knowledge** — evidence supports reuse beyond the source project.
4. **Toolized knowledge** — validator/script/skill enforces or automates the lesson.
5. **Protocol improvement** — structural AIDOS change prevents the entire failure class.

## Promotion test

A candidate is suitable for AIDOS only when it can be stated without depending on the original project identity and would plausibly improve another relevant development goal.

## Provenance

Every promoted learning records:

- stable ID;
- problem/capability/goal classification;
- generalized statement;
- source execution(s);
- evidence references/hashes where practical;
- validation method;
- confidence/status;
- first-seen and last-validated version/date;
- supersedes/deprecated relationships.

## Goal-scoped retrieval

AIDOS knowledge is not globally injected into every execution. Worker selects relevant knowledge by:

```text
core
+ required capabilities
+ development goal/pattern
```

## Preference for executable knowledge

When practical:

```text
lesson
→ validator/tool/skill
```

is preferred over repeatedly spending model context on prose instructions.
